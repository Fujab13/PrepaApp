Configurar Resend como SMTP de Supabase Auth
=============================================

Contexto: el correo de confirmación de registro (y el de "olvidé mi
contraseña") no está llegando porque el proyecto usa el servicio de correo
compartido de Supabase (sin SMTP propio configurado) — ese servicio tiene un
límite muy bajo (pocos correos/hora) y no está pensado para producción.

Ya existe un helper para Resend en supabase/functions/_shared/resend.ts
(enviarCorreo, vía API HTTP de Resend), pero ese es para correos que mande un
edge function a mano (ej. notificaciones a profesores) — es independiente de
esto. Lo que falta configurar es el SMTP de Supabase Auth, que usa el
protocolo SMTP, no la API de Resend.

Pasos:

1. Crear cuenta en resend.com (plan gratis: ~100 correos/día, ~3,000/mes,
   gratis de forma permanente, no es trial).

2. Verificar un dominio propio en Resend (Dashboard → Domains → Add Domain):
   agrega los registros DNS que pida (SPF, DKIM, y DMARC si lo sugiere) en el
   proveedor donde esté el dominio. Sin dominio verificado no se pueden
   mandar correos desde una dirección tipo "no-reply@tudominio.com" (usar el
   dominio de onboarding de Resend solo sirve para pruebas, no producción).

3. Generar credenciales SMTP en Resend (Dashboard → SMTP, o reusar la
   API key como password):
     Host: smtp.resend.com
     Puerto: 465 (SSL) o 587 (TLS)
     Usuario: resend
     Password: la API key de Resend (empieza con "re_")

4. En el Dashboard de Supabase → Authentication → Emails → SMTP Settings:
   - Activar "Enable Custom SMTP"
   - Host / Puerto / Usuario / Password: los de arriba
   - Sender email: una dirección del dominio verificado (ej.
     no-reply@tudominio.com)
   - Sender name: "PrepaApp"

5. Probar: registrar una cuenta nueva con correo/contraseña y confirmar que
   el correo de confirmación llega (revisar spam la primera vez). Repetir
   con "¿Olvidaste tu contraseña?" en Login.jsx.

Nota de costos (meta: 50,000 usuarios sin gastar antes de llegar ahí):
el límite a vigilar es el de "por día" (~100/día en el plan gratis), no el
mensual. Si algún día hay un pico de registros el mismo día (ej. un profesor
comparte la app con muchos alumnos a la vez), ese día se trabarían las
confirmaciones pasado el correo 100. Cuando eso empiece a pasar, subir de
plan en Resend es barato y solo se paga cuando ya haya ese volumen real, no
antes.

Lecciones premium (lo que edité: medicina.json)
